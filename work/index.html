Data quality fix in a live register

Joining two history tables on ID alone multiplied rows in historical data — a cross-join between periods. About 20% of the rows (1,238 of 5,894) were false. I added a period-overlap condition:

AND o.start_dt <=
  NVL(h.end_dt, DATE '9999-01-01')
AND h.start_dt <=
  NVL(o.end_dt, DATE '9999-01-01')

After the fix, views and SELECTs returned clean data. The condition is now an internal standard: it is required in every join with this table, and the team has adopted it in its procedures and views. I also replaced ROWNUM < 2, which picked an arbitrary row, with ORDER BY … FETCH FIRST 1 ROW ONLY, so the query always returns the right row.
